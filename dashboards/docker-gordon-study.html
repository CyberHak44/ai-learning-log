STEP 1 OF 7 · WHY CONTAINERS

"It works on my machine" is the problem Docker solves

Software needs the right versions of many other pieces to run. Install it on a different PC and something is missing or the wrong version, so it breaks. A container packs the software together with everything it needs. The same container runs the same way on your laptop, on a server and at a client's site.

Think of it as

A shipping container. The ship, the crane and the lorry do not care what is inside; the box is a standard size, so it moves anywhere unchanged.

Say it in one line

"A container packages an application with everything it depends on, so it runs identically on any machine. That is how we give every client the same tested build."

STEP 2 OF 7 · IMAGES, CONTAINERS, REGISTRIES

Recipe, cake, and the bakery shelf

A Dockerfile is the written recipe. Building it gives an image: a frozen, read-only package. Running an image gives a container: a live copy that is actually working. One image can run as many containers. Images are stored on a registry such as Docker Hub, where you pull ready-made ones.

CommandWhat it does
docker pull nginxDownload the nginx web server image from Docker Hub
docker run nginxStart a container from that image
docker psList the containers that are running
docker build -t ie-tool .Build an image called ie-tool from the Dockerfile in this folder
Say it in one line

"A Dockerfile builds an image, an image runs as one or many containers, and images live in a registry like Docker Hub."

STEP 3 OF 7 · PORTS AND STORAGE

Doors in, and a cupboard that survives

A container is sealed by default. To reach it you open a port: a numbered door from the machine into the container. A container also forgets everything when it is deleted, so anything worth keeping, such as logs or a database, goes in a volume: storage that lives outside the container.

Think of it as

A hotel room. The port is the room number reception gives a guest. The volume is the safe in the basement: the guest checks out, the safe keeps its contents.

CommandWhat it does
docker run -p 8080:80 -v ie-logs:/data nginxOpen machine port 8080 to container port 80, and keep /data in a volume called ie-logs
Say it in one line

"Ports let traffic in, volumes keep data when containers are replaced. Open only the ports you need."

STEP 4 OF 7 · DOCKER COMPOSE

Several containers, one command

Real services are made of parts: something that collects data, a database, a dashboard. Docker Compose describes all the parts in one file, compose.yaml, and starts them together with one command. This file is how one tested build can be repeated for every client.

Say it in one line

"Compose describes a whole service in one file, so we install the same tested IE Watch stack at every client with one command."

STEP 5 OF 7 · GORDON AND THE MCP TOOLKIT

An AI assistant that knows Docker, and a safe way to give AI tools

Gordon is the AI assistant inside Docker Desktop. Ask it why a container will not start, or to write a compose file, and it explains and fixes. It can run Docker commands, but only when you allow it. The MCP Toolkit connects AI assistants such as Gordon to tools (GitHub, files, databases), each tool running in its own container with only the access you give it.

Think of it as

An apprentice who knows Docker inside out. Gordon proposes the fix; you approve before anything changes. MCP is the set of keys you hand the apprentice, one key per room, never the master key.

Say it in one line

"Gordon is Docker's built-in AI assistant; the MCP Toolkit gives AI assistants controlled, per-tool access, which is least privilege applied to AI."

STEP 6 OF 7 · DOCKER MODEL RUNNER

A private AI that never leaves the building

Docker Model Runner downloads an AI language model and runs it on a local machine. Questions and documents stay on that machine; nothing goes to a cloud AI provider. That is the idea behind a private on-site AI box, and the answer to a bank CISO who asks where client data goes.

CommandWhat it does
docker model pull ai/smollm2Download a small model from Docker Hub's ai/ collection
docker model run ai/smollm2Start it and chat with it locally

Model names change; check the ai/ collection on Docker Hub for current ones. Bigger models need more memory and ideally a graphics card.

Say it in one line

"Docker Model Runner runs the AI model on the client's own hardware, so confidential documents never leave the building."

STEP 7 OF 7 · KEEP CONTAINERS SECURE

Containers are software too. They need patching and limits.

A container image can carry old, vulnerable libraries. A container running as the all-powerful root user can do far more damage if it is broken into. These five habits keep IE's builds safe, and each maps to an ISO 27001 control you can show an auditor.

HabitWhyISO 27001
Use official or hardened images, pinned to a versionYou know what you are running and it does not change silentlyA.8.9
Scan images for known flaws (docker scout)Finds vulnerable libraries before a client gets themA.8.8
Do not run containers as rootLimits damage if one is compromisedA.8.2
Never put passwords or keys inside an imageImages get copied and sharedA.5.17
Open only the ports you needSmaller attack surfaceA.8.20
Say it in one line

"Pin and scan images, never run as root, keep secrets out of images, expose only needed ports; each one is evidence for an ISO control."
